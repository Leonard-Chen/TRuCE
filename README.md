# TRuCE: Document-Level Relation Extraction with Type and Text Evidence Conflicts

**English** | [简体中文](./README.zh-CN.md)

## Requirements

- Python 3.9 or later
- GPU: NVIDIA GeForce RTX 3090 (24GB)
- CPU: 14 vCPU Intel(R) Xeon(R) Gold 6330 CPU @ 2.00GHz
- Dependencies:
  - [PyTorch 2.8](https://pypi.org/project/torch/2.8.0/)
  - [Transformers 4.57.6](https://pypi.org/project/transformers/4.57.6/)
  - [bert-base-uncased](https://huggingface.co/google-bert/bert-base-uncased/tree/86b5e0934494bd15c9632b12f734a8a67f723594)
  - [Re-DocRED](https://github.com/tonytan48/Re-DocRED)

Please run the commands below from the project root. On Windows PowerShell:

```powershell
.\scripts\setup.ps1
.\.venv\Scripts\Activate.ps1
```

On CentOS Linux 7:

```bash
bash scripts/setup.sh --python python3
source .venv/bin/activate
```

```text
runs/

 |    |    |-- epoch_01.json      # Training records saved after each epoch's validation
 |    |    |-- ...
 |    |-- best/
 |    |    |-- model.safetensors
 |    |    |-- checkpoint.json
 |    |    |-- dev_clean.json
 |    |    |-- dev_confusion20.json
 |    |-- last/training.pt
 |    |-- metrics.csv
 |    |-- tensorboard/
 |         |-- events.out.tfevents.*

artifacts/
 |-- teachers/                   # Generated by prepare_teachers.py
 |    |-- manifest.json
 |    |-- train.json
 |    |-- dev.json
 |    |-- test.json
 |    |-- confusion.json
 |    |-- *.safetensors          # Local/document type-head weights
 |    |-- *.npz                  # Frozen features and OOF logits
```

Each variant directory inside a smoke run contains the training files shown above, plus `test_<condition>.json`, `test_<condition>.predictions.json` and `diagnostics.json`. Smoke teachers are stored inside that smoke run, separately from the formal teacher cache in `artifacts/teachers/`.

`best/` is created after a successful development-set evaluation; `last/training.pt` stores the full state for resuming training. TensorBoard logging is enabled by default but can be disabled or redirected. PNG/PDF figures are created only by running `scripts/plot_metrics.py`, in its specified `--output-dir`; training does not generate figures automatically.

## Training

### 1. Environment Check

```bash
python -m truce doctor
python -m truce smoke --output runs/first_smoke
```

To also validate E1:

```bash
python -m truce smoke --include-etmier --output runs/all_smoke
```

>P.S. E1 requires the pinned ET-MIER source:
>
>```bash
>git clone --config core.autocrlf=false https://github.com/xin-fight/ET-MIER.git external/ET-MIER
>git -C external/ET-MIER checkout --detach c0650a930b065709e1c18d93400486b4be03832c
>```

Resume an existing training run:

```bash
python -m truce train --resume "runs/B8_seed17"
```

### 2. Data Preparation

```bash
python scripts/download_data.py --output-dir data/raw
python -m truce audit --config configs/B0.yaml --output artifacts/data_audit.json
python scripts/prepare_teachers.py --config configs/B0.yaml --output artifacts/teachers
```

### 3. Training

```bash
python -m truce train --config configs/B0.yaml --output runs/B0_seed17
python -m truce train --config configs/B1.yaml --output runs/B1_seed17
python -m truce train --config configs/B8.yaml --output runs/B8_seed17
```

Small-sample interface check:

```bash
python -m truce train --config configs/B1.yaml --output runs/B1_pilot --set training.limit_train=32 --set training.limit_dev=16 --set training.max_steps=10 --set training.epochs=2
```

Experiment configurations:

| Config | Treatment                                                  |
| --- |------------------------------------------------------------|
| B0 | No external types used; retain the text and graph backbone |
| B1 | Directly use observed types                                |
| B2 | B1 + type-dropout=0.2                                      |
| B3 | B1 + type residual fixed scaling lambda=0.5                |
| B4 | B1 + replace all with q_doc                                |
| B5 | B1 + gating after type propagation                         |
| B6 | B1 + C (soft correction)                                   |
| B7 | B1 + G (pre-propagation suppression)                       |
| ★B8 | B1 + C + G (soft correction + pre-propagation suppression)                            |
| E1 | Controlled single-model adaptation of ET-MIER              |

Experiment plan:

```bash
python -m truce matrix --config configs/B0.yaml --output runs/main_plan
```

Execute (use a new directory distinct from the plan preview):

```bash
python -m truce matrix --config configs/B0.yaml --output runs/main_runs --execute
```

Execute a smaller selection (optional):

```bash
python -m truce matrix --config configs/B0.yaml --output runs/pilot_runs --variants B0 B1 B3 B8 --seeds 17 --execute
```

Without `--execute`, only a plan is generated. A directory containing `matrix.json` cannot be reused to create or execute a matrix. Batch training does not automatically run `sweep`. Models are stored under `runs/main_runs/<variant>_seed<seed>/`, which differs from the individual-run paths used below; evaluate the actual run directory. For example, after batch training:

```bash
python -m truce sweep --checkpoint runs/main_runs/B8_seed17 --split dev --output runs/main_runs/B8_seed17/dev_sweep
```

If interrupted, use `train --resume "runs/main_runs/B8_seed17"` with the actual interrupted run. The current `matrix` command does not automatically resume a matrix or continue its remaining jobs.

E1:

```bash
python -m truce train --config configs/E1.yaml --output runs/E1_seed17
python -m truce sweep --checkpoint runs/E1_seed17 --output runs/E1_seed17/noise_sweep
python -m truce diagnose --checkpoint runs/E1_seed17 --output runs/E1_seed17/diagnostics.json
```

### 4. Type Interventions and Evaluation

| Condition | Name | Description                                                                         |
| --- | --- |-------------------------------------------------------------------------------------|
| C0 | clean | Original reference types, without manual modifications                              |
| C1 | missing | Types are missing for some entities                                                 |
| C2 | uniform | Types of some entities are randomly corrupted                                       |
| C3 | confusion | Types are corrupted according to common confusion patterns of the type classifier   |
| C4 | local | Uses the types actually predicted by a local type classifier, making natural errors |

```bash
python -m truce intervene --config configs/B8.yaml --split test --condition confusion --rate 0.2 --noise-seed 101 --output artifacts/test_C3_20_seed101.json
python -m truce evaluate --checkpoint runs/B1_seed17 --condition confusion --rate 0.2 --noise-seed 101 --output runs/B1_seed17/test_C3_20.json
python -m truce evaluate --checkpoint runs/B8_seed17 --condition confusion --rate 0.2 --noise-seed 101 --output runs/B8_seed17/test_C3_20.json
python -m truce sweep --checkpoint runs/B8_seed17 --output runs/B8_seed17/noise_sweep
python -m truce diagnose --checkpoint runs/B8_seed17 --output runs/B8_seed17/diagnostics.json
```

Paired bootstrap:

```bash
python -m truce bootstrap --config configs/B8.yaml --a runs/B1_seed17/test_C3_20.json --b runs/B8_seed17/test_C3_20.json --output runs/bootstrap_B8_minus_B1.json
```

### 5. C5 Evidence Sensitivity

Mask part of the evidence to test whether the model relies on it.

```bash
python -m truce evidence --checkpoint runs/B8_seed17 --split dev --source predicted --limit 100 --output runs/B8_seed17/evidence_predicted.json
python -m truce evidence --checkpoint runs/B8_seed17 --split dev --source reference --limit 100 --output runs/B8_seed17/evidence_reference.json
```

## Additional Notes

- `smoke` uses a randomly initialized small encoder and is only for pipeline validation, not for paper results.
- Do not use `artifacts/toy_teachers` or smoke caches for formal data.
- In E1, external types only enter the auxiliary training loss; at inference, types are predicted from text. The main mechanism evidence still comes from B1/B6/B7/B8.
- E1 verifies the raw file hashes of its adapters when loading. Source-byte changes, including adding a shebang, affect old-checkpoint validation. Resume an old E1 experiment with its matching code version; do not rewrite provenance hashes in the checkpoint.
- The current repository structure still has room for optimization; directory hierarchy and script modularization will be adjusted later.
